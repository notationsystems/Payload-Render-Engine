# API surface - the authorized planes

Every served route, the plane that admits it, the limb its answer carries, and the product that owns it.

**Scope.** This describes the Payload Render Engine - a read-only
projection over a corpus it does not own. It is not a description of a
deployed Caravan, Tradewind or Landshark service, and nothing here is
evidence that one exists.

**MEASURED** sections are read from the registers when this file is
generated. **AUTHORED** sections are decisions, and live in the
generator so there is still one source.

## AUTHORED - the invariant

> **API-000.** every ok answer carries exactly one of meta.reference (canonical + proof root), meta.derivation (derived from a build by a named method) or meta.observation (operational + limitations) - never more than one, never none

**This twin is a superset of the bundle's API-000.** As the
ecosystem states it, the invariant has two limbs
(`CANONICAL_PROOF`, `OPERATIONAL_OBSERVATION`). This
surface adds `VERIFIED_DERIVATION`, because
the canonical limb promises membership of the committed build; a value the service COMPUTED from that build is not a member of it, and no inclusion proof will ever be produced for one. Splitting the limb keeps the promise true rather than weakening it. if the bundle adopts it, API-000 gains a third limb and the ecosystem/api-planes.json statement widens. Until then this twin is a superset and says so.

Three independent facts travel with every route. None is derivable from
the others, and `API-004` fails if they ever collapse.
